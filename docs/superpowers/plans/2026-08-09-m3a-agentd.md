# M3a agentd 自动同步回路 实现计划

**Goal:** 让 `arca-agentd` 跑起来——每数据集独立的自动调和回路，把 M2 建好的手动同步
变成不用敲命令的同步。

**Architecture:** **agentd 是 `arca-cli` 的消费者，不是它的平行实现。**
决策来自 `arca-core`，执行来自 `arca_cli::sync`，agentd 只负责
「什么时候调它」与「失败了怎么退避」。

**Tech Stack:** Rust 2021 / MSRV 1.85 · tokio（agentd 允许）· 已有的 `arca-cli`

---

## 为什么 agentd 必须复用 arca-cli 而不是自己实现

CLAUDE.md 的分层降级关系：

```
手动 CLI（基线，必须完整可用，无需任何 daemon）
  └─ arca-agentd（可选：自动同步）
```

「上层是下层的增强」在代码上的含义只有一个：**agentd 调的就是 `arca sync` 调的那段代码。**
如果 agentd 自己写一套调和执行，两条路会分叉——M2d 的评审在 `Transport` 上抓过同构的问题
（「角色在一种传输上被尊重、在另一种上被忽略」）。分叉之后，用户报「手动同步没事、
自动同步丢东西」时没人能解释。

`arca-cli` 有 lib 目标，且与 `arca-agentd` 同为 MIT，依赖方向合法。

## Global Constraints

- MSRV **1.85**，edition 2021。依赖要求高于 1.85 **报告而非降级钉版**。
  **每个任务自己跑完四项门禁再交**——M2e Task 4 跳过了这一步，门禁断了一整个切片才被发现。
- `#![forbid(unsafe_code)]` 保持。**`arca-core` 一行不改**。
- tokio 只允许在 `arcad` 与 `arca-agentd`。**`arca-cli` 的 tokio 节点数必须仍为 0**——
  agentd 依赖 arca-cli 不能反过来把运行时带进 CLI（`arca-cli` 不依赖 agentd，方向是安全的，
  但要用 `cargo tree -p arca-cli | grep -c tokio` 实测确认）。
- 只在 `main` 分支工作。提交信息、文档、注释一律中文。
- **I11**：一个 hub 不可达 → 只有它承载的数据集离线，其余照常同步。
- **I3**：agentd 不得引入任何新的销毁路径。它调的是同一个 `sync()`，四道闸门照旧。
- **agentd 崩了，手动命令必须照常工作**——这是可执行断言，不是文档承诺。

- [ ] 测试：起两个实例，第二个退出非 0 且说清原因；发 SIGTERM 后进程真的退出且退出码为 0。

### Task 2: 每数据集独立回路 + 退避 ✅ 已完成（2622bf9、验收 ef9d325）

**Files:** `crates/arca-agentd/src/syncer.rs`

- [ ] 每个数据集一个独立 task：独立的游标、独立的退避状态、独立的健康度。
- [ ] 调和一轮 = 调 `arca_cli::sync::sync_transport(...)`（**就是手动命令调的那个**）。
      阻塞 IO 必须走 `spawn_blocking`——M2c 的 I6 教训：阻塞工作直接跑在 tokio worker 上，
      2–4 核 NAS 上会把 worker 占满，连 I11 的 503 都发不出去。
- [ ] 指数退避 + 抖动，上限封顶（建议 60s）。**退避状态每数据集独立**。
- [ ] **一个数据集的 panic 不能带走整个 daemon**——用 `JoinHandle` 的错误处理，
      崩掉的回路记录、重启，其余数据集不受影响（I11 的进程内镜像）。
- [ ] 测试：两个数据集分属两个 hub，断开其一 → 另一个**实际完成了同步**
      （断言文件真的传过去了，不只看日志）；坏掉的那个在恢复后自己接上。

## Self-Review

**范围**：占位符层与分级驻留是 **M3c/M3d**，本切片不碰——agentd 在 M3a 仍是全量物化，
只是不用人敲命令了。watcher（本地变更实时检测）是 **M3b**：本切片的本地侧靠周期扫描，
够用且诚实。

**最容易写错的地方**是 Task 2 的「一个 hub 挂了不影响其余」——用 `?` 中止整个循环是
最自然也最错的写法，M2d 在同构的位置踩过。测试要断言**其余数据集的文件真的传过去了**。

**第二容易错的**是 agentd 自己重新实现一遍同步。任何时候发现自己在 agentd 里写
「决定该传什么」的代码，就是走错了——那段代码已经在 `arca-core` 与 `arca_cli::sync` 里。
