# M1c arca-git 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 arca 与 git 的接缝：`.gitignore` 反选块、清单同步、pre-push 一致性钩子、追踪冲突检测。

**Architecture:** arca 与 git **并行**工作，不做 clean/smudge filter（寄生 git 管道正是 Git LFS 的失败根源，spec §1.2）——只共享目录、`.gitignore` 与清单。`arca-git` 会真的调用 `git` 命令，它不受 sans-io 约束（那只约束 `arca-core`）。

**Tech Stack:** Rust 2021 / MSRV 1.85 · arca-format（注册表与清单）· `std::process::Command` 调 git · tempfile（dev）

---

## 为什么这块的风险最高

CLAUDE.md 把 `.gitignore` 反选块列为**全设计最易出错处**。原因是 git 的一条规则：
**父目录被排除后，其内容无法再被反选**。所以不能直接写 `/assets/`，而必须

```gitignore
/assets/*
!/assets/.arca/
/assets/.arca/client/
```

写错一个字符，后果是两个方向的灾难：

- 反选没生效 → `.arca/` 元数据没进 git → **协作者拿不到清单**，克隆后看到的是一个
  空目录和零线索
- 排除没生效 → **整个数据集被误提交进 git** → 仓库爆炸，而且已经进了历史，
  瘦身要重写历史

因此本切片有一条不可谈判的纪律：**断言 `git check-ignore` 的实际结果，而不是文本**。
文本比对能通过而行为是错的——这正是最危险的失败形态。

**Interfaces:**
- Produces:
  - `repo::Repo`：`open(path: &Path) -> Result<Repo, GitError>`（校验是 git 仓库）；
    `check_ignore(&self, path: &str) -> Result<bool, GitError>`（**调真的 `git check-ignore`**）；
    `ls_files(&self) -> Result<Vec<String>, GitError>`；`root(&self) -> &Path`
  - `GitError`：`NotARepo{path}` / `GitNotFound` / `CommandFailed{cmd, code, stderr}` / `Io{..}`，
    实现 `Display`（中文）+ `Error`
  - `ignore_block::{render(datasets: &[&str]) -> String, upsert(existing: &str, datasets: &[&str]) -> String, remove(existing: &str) -> String}`

- [ ] **Step 1: 定下块的确切形态**

```gitignore
# >>> arca managed (do not edit inside) >>>
/assets/*
!/assets/.arca/
/assets/.arca/client/
/photo/*
!/photo/.arca/
/photo/.arca/client/
# <<< arca managed <<<
```

规则：数据集按**路径字节序排序**（确定性，同一组数据集必产生同一字节）；
每个数据集恰好三行，顺序固定；块外的用户内容**逐字保留**；
`upsert` 幂等——对已有块的内容再跑一次必须产出完全相同的字节。

- [ ] **Step 2: 写失败的测试——断言 `git check-ignore` 的实际结果**

这是本任务的核心，测试必须真的建仓库：

```rust
//! `.gitignore` 反选块——全设计最易出错处（spec §4.3、§6.3 第 9 条）。
//!
//! **断言的是 `git check-ignore` 的实际行为，不是文本。** 文本比对能通过而行为是错的，
//! 那正是最危险的失败形态：反选没生效则协作者拿不到清单；排除没生效则整个数据集
//! 被误提交进 git。

use std::path::Path;
use std::process::Command;

fn 建仓库(dir: &Path) {
    for args in [
        vec!["init", "-q"],
        vec!["config", "user.email", "t@example.com"],
        vec!["config", "user.name", "t"],
    ] {
        let ok = Command::new("git").args(&args).current_dir(dir).status()
            .expect("需要可用的 git").success();
        assert!(ok, "git {args:?} 失败");
    }
}

#[test]
fn 受管二进制被忽略而_arca_元数据被追踪() {
    let dir = tempfile::tempdir().unwrap();
    建仓库(dir.path());
    std::fs::create_dir_all(dir.path().join("assets/.arca/client")).unwrap();
    std::fs::write(dir.path().join(".gitignore"),
        arca_git::ignore_block::render(&["assets"])).unwrap();

    let repo = arca_git::repo::Repo::open(dir.path()).unwrap();
    // 受管二进制：必须被忽略
    assert!(repo.check_ignore("assets/京都/鸭川.png").unwrap(), "受管二进制必须被忽略");
    // 元数据：必须被追踪（反选生效）
    assert!(!repo.check_ignore("assets/.arca/dataset.toml").unwrap(), ".arca/ 必须能进 git");
    assert!(!repo.check_ignore("assets/.arca/manifest").unwrap(), "清单必须能进 git");
    // 本地投影：必须被忽略（设备差异不进共享配置）
    assert!(repo.check_ignore("assets/.arca/client/state.db").unwrap(), "client/ 必须被忽略");
}
```

再补：多数据集、块外用户内容被保留、`upsert` 幂等、`remove` 只删块、
数据集路径含非 ASCII（`资料/`）时仍正确。

### Task 2: 追踪冲突检测与 vault 一致性

**Files:**
- Modify: `crates/arca-git/src/tracking.rs`
- Test: 内联 + `tests/ignore_block.rs` 追加

**Interfaces:**
- Produces: `tracking::{check_vault(repo: &Repo, registry: &Registry) -> Vec<Issue>, Issue}`
  - `Issue` 变体覆盖 spec §4.3.2 的处置表：`OrphanDataset{path}`（有 `.arca/` 但不在注册表）、
    `MissingDataset{path}`、`HubIdMismatch{path, expected, found}`、`NestedDataset{outer, inner}`、
    `DuplicatePath{path}`、`AlreadyTracked{path}`（**已被 git 追踪的文件落入数据集**）

**`AlreadyTracked` 为什么单独一条**：`.gitignore` 对**已追踪**的文件无效。
一个先被 `git add` 过、后来落进数据集目录的文件会继续被 git 追踪，
于是同一份数据被 git 与 arca 双重管理——spec §4.3.1 把这列为 glob 方案的致命伤之一，
目录方案本该结构上不可能发生，但**用户手工 `git add` 仍能制造它**，所以要检出。

- [ ] 测试：每个 `Issue` 变体各一条；`AlreadyTracked` 要真的 `git add` 一个文件再断言检出。
- [ ] `check_vault` **只报告不修复**（I5：停下并可诊断）。

### Task 3: pre-push 钩子

**Files:**
- Modify: `crates/arca-git/src/hooks.rs`
- Test: 内联 + 集成

**Interfaces:**
- Produces: `hooks::{install_pre_push(repo: &Repo) -> Result<InstallOutcome, GitError>,
  uninstall_pre_push(repo: &Repo) -> Result<(), GitError>, InstallOutcome}`
  - `InstallOutcome`：`Installed` / `AlreadyInstalled` / `RefusedForeignHook{existing_path}`

**纪律**（spec §4.4.2）：钩子**只读不改**——从不修改提交、从不自动 push，
只做一致性断言。已存在非 arca 的 pre-push 钩子时**拒绝覆盖**并报告
（`RefusedForeignHook`），绝不静默替换用户的钩子（I6）。

钩子脚本本身是 POSIX shell，内容只做一件事：调 `arca` 检查本次推送涉及的清单条目
是否都已在 hub 落地，未落地就以非零码退出并列出未上传文件。
**M1c 只负责安装与卸载**，钩子里调的那个检查命令属 M1d。
所以本任务生成的脚本应当调用一个**约定好的命令名**，并在 M1d 未就绪时优雅降级
（命令不存在 → 打印提示并放行，不阻塞用户的 `git push`）。

- [ ] 测试：安装后 `.git/hooks/pre-push` 存在且可执行；重复安装是幂等的；
  存在他人的钩子时拒绝且**不覆盖**；卸载只删 arca 自己装的那个。

### Task 4: 噩梦路径（spec §6.3 第 9 条）

**Files:**
- Create: `crates/arca-git/tests/nightmare.rs`

spec §6.3 第 9 条点名要求验证的三件事——**git 的日常操作不得误伤受管二进制**：

- [ ] `git checkout` 切分支后，受管二进制仍在原地（未被删除、未被改名）
- [ ] `git clean -xdf` **不删除**受管二进制
      （注意：`-x` 会删被忽略的文件，所以这条如果失败是真问题——
      要在测试注释里写明用户遇到这种情况的后果，以及 `arca doctor`
      为什么要检出「本地存在但 hub 尚无副本」的文件）
- [ ] `git stash` 不影响受管二进制

每条都要真的跑那个 git 命令，然后断言文件系统的实际状态。

**如果 `git clean -xdf` 那条失败**：那不是测试太严——受管二进制确实会被 git 当作
被忽略的文件删掉。这是 spec §13 风险表里列出的已知风险（「git 操作误伤」）。
此时**停下报告**，不要改测试迁就，我们需要决定是接受这个风险并在文档里写明，
还是调整 `.gitignore` 的写法。
