## 这块闭合了什么

M2d 的评审把「本地回收站是只写的」称为**最大的一条 carry-forward**：

> spec §4.7 说 server 角色的 tombstone「移入本地 trash **保留期**，物理销毁只经显式 GC」——
> 但当时没有保留期概念、没有 GC、没有 `restore` 通路、没有列表、`doctor` 也看不见它。
> **今天恢复要手读 `.data`/`.meta`，而 server 设备的 trash 会无界增长。**

那是一个存储产品不该跨里程碑保留的状态：M2d 刚刚承诺「server 角色永不释放空间」，
紧接着就让那份被保住的数据只能靠手读字节找回来。

### `arca gc`：把「绝不销毁」变成一条边界，而不是一句口号

README 第一屏承诺「arca 里没有任何一条代码路径能在你不知情时销毁数据」。
在此之前这句话成立得很容易——**没有任何代码路径能销毁数据**。gc 是第一次
真的开一个口子，所以边界必须被实机验过，而不是被读过。

我对真实二进制跑了 8 组攻击，全部守住：

| 攻击 | 结果 |
| --- | --- |
| 不带任何开关 | 默认即 dry-run，文件系统指纹**逐字节不变** |
| `--yes` 但条目在 180 天保留期内 | 一条不动 |
| `--include-unexpired` 不配 `--yes` | 什么都不删 |
| `--retention-days 0` 不配 `--yes` | 什么都不删 |
| `--dry-run` 与 `--yes` 同时给出 | 退出 1，「已停止，什么都没做」——绝不取其一继续（I5） |
| `--retention-days 0 --yes` | 真的销毁，**并列出销毁清单**；存活的受管文件与 hub 侧内容毫发无损 |
| 孤儿 `.data`（无 `.meta` 认领） | 退出 1，**一个字节都没销毁**（包括那些本身健康、已过期的条目） |
| `.meta` 内容损坏 | 退出 1，拒绝判断 |

外加一条结构性核实：**`gc::` 除命令壳外零调用者**——没有任何定时器、没有任何
「顺手清理」。cron 里写 `arca gc` 是用户的主动决策。

### TLS：绝不 TOFU

系统根证书静默通过；自签名要求**先带外核对指纹再 pin**，指纹变更即拒连。
测试守住三条性质，全部用真的 rustls 握手而不是 mock：正确 pin → 连通；
pin 不符 → 拒连且报出两个指纹、告诉用户下一步；无 pin 的自签名 → 拒连，
**且绝不顺手把指纹记进 `.gitarca`**（那就是 TOFU）。

`arca-cli` 依赖树里 tokio 节点数仍然是 **0**——`rustls` 选的是不强制异步的配置。

## 评审抓到了什么

### 门禁 4 从 M2e Task 4 起就断了，直到 Task 5 收尾才被发现

`cargo +1.85 check --workspace --locked --all-targets` 在 `f0c4618` 之后一直失败。
二分确认：`4ac23df` / `0f50fa1` / `421fb75` 通过，`f0c4618` 起失败。

成因：TLS 测试引入 dev-dependency `rcgen`，它把 `time` 拖进了**构建图**——
而 `ureq` 的 `cookie_store` 要求 `time ^0.3.47`，该区间内每一个 `time` 都要 rustc 1.88。
（`time` 早就在锁文件里，只是在此之前不在构建图里，所以一直没事。）

**MSRV 是对用户的承诺，不该被一个只在测试里用一次的依赖拉低**——发布出去的
二进制本身在 1.85 上编得好好的，被卡住的只有测试。钉版走不通（`time` 全区间都要
1.88，`rcgen` 0.13/0.14 自身也要 1.88），所以去掉 `rcgen`，改用提交进仓库的
自签名证书夹具（P-256、SAN=localhost、CA:FALSE + serverAuth、有效期到 2126 年）。
所有指纹本来就由 `fingerprint(der)` 在运行时算，固定一张证书不削弱任何一条断言——
7 个 TLS 测试全部照常通过。

**教训：一个切片自己不跑门禁，下一个切片会替它跑。** 前四个切片的收尾都跑了四项门禁，
Task 4 是第一次在任务内部跳过。

### bugreport 的 trace 那一节列错了一层

实机跑一份报告才看出来：trace 会话文件落在 `<state>/trace/`，而代码列的是 `<state>` 本身，
于是输出只有一行「`trace` 目录、1664 字节」——**52 个真正的会话文件一个都看不见**，
而这一节的全部价值就是让人知道有哪些会话可以附上。

补了回归测试，并**验证过去掉修复它真的会失败**（退化版本还会谎称「没有任何 trace
落盘文件」，比列错更糟）。光跑测试看不出这个问题，只有实机跑才行——
这一条和 M0 逃生舱、M2b 的 curl 验证是同一个模式。

### 一条我先判错又收回的

实机攻击 gc 时，「有 `.meta` 但磁盘上没有 `.data`」的条目被静默销毁、报告「回收 0 字节」，
我一开始判成缺陷（销毁了「丢的是哪个文件」的最后一条线索）。读完 `gc::plan` 的设计与
既有测试之后收回：**gc 自己的销毁顺序就是先 `.data` 后 `.meta`**，中途崩溃恰好留下这个
状态，补删是自愈；把它当 blocker 会让任何一次 gc 崩溃**永久堵死后续所有 gc**；
而且只对已过保留期的条目这么做，保留期内的孤儿 `.meta` 会留给 `doctor`/`restore` 报告。

真正缺的只是**选了自愈之后没说出来**——那是 I5 的诊断面：不猜，但也不闷声。
补了一句单独点名，并配正反两面的回归测试（无内容条目必须点名，全正常时不许冒出这句话）。

## bugreport 的隐私边界是可执行的

一条命令收齐：版本、平台、git 版本、最近的 trace 落盘文件、各数据集的
`dataset_id` / 角色 / hub 可达性 / `.gitignore` 反选块的**实测**结果 /
本地回收站占用与清单、`doctor` 的结论。M2d 评审点名的两项——`role.toml` 与
本地回收站清单——都进了报告：**角色正是那种「解释为什么这台设备行为和那台不同」
的设备本地状态**，而在此之前所有诊断命令都看不见它。

「绝不收集文件内容」不是文档承诺：测试往受管文件与回收站副本里各塞一串独一无二的
魔法串，断言整份输出搜不到它们，**并先自证魔法串确实在磁盘上**——否则测试会因为
「根本没造出来」而假绿，那是最坏的一种通过。

报告只走 stdout，不落盘、不上传：用户在按回车之前就能把收了什么看个遍。
bugreport 自身成功就退出 0，即便报告里记录了一堆问题——退出码回答的是
「这条命令跑成功了吗」，不是「你的库健康吗」（后者是 `doctor` 的职责）。

## 真正缺的，按优先级

1. **副本计数仍看不到其它设备**——需要 hub 侧登记每个绑定设备的角色，
   要认证与设备注册，正确地推后了（告警文案已诚实披露这是「已知的下限」）
2. **`verify --deep` 在网络上的代价**——默认只校验元数据一致性，
   帮助文本已写清默认模式验什么、不验什么，但大库上的 `--deep` 还没有做过基准
3. `.arca/chunks/` 下的块**一个都不会被 gc 回收**——块级引用模型在写入侧还不存在，
   凭现有信息判断「哪个块失引用」必然出错，因此选择不猜（I5）。gc 会明说这一点
4. `journal_store.rs` 仍是骨架，**journal 压缩尚未实现**（自 M2c 起的老账）
