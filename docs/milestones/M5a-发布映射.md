# M5a · 发布映射（publish-map）

**完成于 2026-08-09** · 3 个提交 · 结束时 858 个测试全绿

M5 头条验收的核心：**CI 在不下载任何 blob 的前提下构建出图片可访问的静态站**。

---

## 交付了什么

`arca publish-map [--all] [--out <路径>]`——产出站点生成器消费的
`publish-map.json`（spec §4.9）。

| 部分 | 内容 |
| --- | --- |
| `map` | `{schema, datasets, items}` 的构造与序列化 |
| `referenced` | md 引用提取（标准链接 / wiki 链接 / HTML `src`） |
| 命令壳 | 默认 `--referenced-only`，`--all` 必须显式 |

---

## 两条被测试锁住的性质

### 一个 blob 都不读

清单（§4.4.1）里已有路径、哈希、大小，而链接重写只需要这三样。
100 GB 的图库，CI 一个字节都不用下载。

**这条是被类型保证的，不是「顺便实现成这样」**：`map` 模块的签名里没有
任何能读内容的东西——输入是 `Manifest` 与 `DatasetConfig`，不是目录路径、
不是 `Transport`。它在类型上就做不到去下载 blob。

验法：把受管二进制的内容**彻底换掉但不重新同步**，再跑一次，断言输出
**逐字节相同**。命令若读了 blob，哈希会跟着变——这比数 syscall 更直接，
也不依赖平台。

### 默认只发布被引用的资源

> 直接公开整个数据集会暴露没被任何已发布笔记引用的文件——**这是隐私事故
> 的常见来源**（spec §4.9 约束 ③）。

实机验过：一个 vault 放一张被引用的图与一张「私密照」，默认输出里私密照
出现 **0** 次，`--all` 下出现 **1** 次。

`referenced` 模块的文档写清了这里的取舍——**漏报与误报的代价完全不对称**：

- **漏报**（该发布的没发布）→ 站点上一张图裂了。用户立刻看得见，一眼能修。
- **误报**（不该发布的发布了）→ 一张私密照片挂上了公网 CDN。用户看不见，
  且**不可撤回**（已经被抓取、被缓存）。

所以语法上尽量宽（md 链接、wiki 链接 `[[…]]`、HTML `src` 都认），
结果上严格闭合（只有真的出现在某篇 md 里的路径才进集合，绝不做
「这个目录看起来都该发布」这类推断）。

## 三处边界

- **绝对 URL / 协议相对 URL / `data:` / `mailto:` 一律跳过**——不是本 vault
  的资源，收进来只会污染集合。
- **数据集前缀匹配按路径分量而不是字符串前缀。** `assets` 不该把
  `assets-old/私密.png` 算进来。字符串前缀匹配是「把不该发布的东西发出去」
  的经典途径——与 `arca-agentd` 的 `.arca` 判定是同一条教训，那次是把
  `my.arca-notes/` 误判成内部状态。
- **没配 `public_base_url` → 拒绝**，不用空前缀凑合。空前缀会产出一堆
  `/assets/x.png` 这样看似成功的相对链接，发布出去全是死链（I5）。

## 真正缺的，按优先级

1. **`arca publish` / `arca export` 尚未实现**（§4.9 约束 ④）。目前只有
   「产出映射」，没有「把 blob 推到静态托管」或「hub 开只读公开端点」
2. **参考过滤器没有写**。spec 说「官方仓库提供参考实现」——Hugo / Eleventy /
   Quartz / Zola 各需要一个几十行的过滤器消费 `publish-map.json`。
   没有它，这份映射对用户来说还是半成品
3. **`url_style = "hash"` 只是记录在映射里，没有产出实际 URL**。
   站点生成器要自己按 `{base}/blake3/<hex>` 拼——这个约定应当进 PROTOCOL.md
   或一份发布格式文档，目前只在 spec §4.9 的表格里
4. **Git LFS 迁入桥**（M5 的另一半）完全没开始
