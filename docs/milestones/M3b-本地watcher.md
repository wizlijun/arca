# M3b · 本地 watcher 与 agentd 可观测性

**完成于 2026-08-09** · 3 个提交 · 结束时 809 个测试全绿

补齐 spec §5.2 的客户端变更检测三重保险，并让 `arca status` 看得见 agentd。

---

## 交付了什么

| 部分 | 内容 |
| --- | --- |
| 本地 watcher | `notify` 实时事件 → 去抖合并 → 溢出即全扫 |
| 接进等待循环 | 本地唤醒 / 远端 longpoll / 周期到点 / 停止信号，四路同时盯 |
| 降级路径 | 监听不可用 → 退回纯周期模式并说明，agentd 照常工作 |
| agentd 心跳 | `<vault>/.arca/agentd-status.json`（FORMAT.md §9.7） |
| `arca status` | 报告 agentd 在不在跑、上次成功、是否实时监听 |

**实测：本地改动在 0.7 秒内被同步，而间隔设的是 120 秒**——差两个数量级，
证明是被唤醒而非睡到点。

---

## 唯一的纪律：watcher 说「有动静」，全量扫描说「动了什么」

spec §5.2 的三层是：实时事件 → **溢出即全扫** → 周期性全量对账地基。
关键在中间那层——**实时事件是不可靠的**：内核缓冲区会溢出，事件会被合并、
丢弃、乱序；网络盘、容器挂载、某些文件系统根本不发事件。三重保险第二层
存在的全部理由，就是承认第一层不可靠。

所以 `Wake::Changed` 只带**一个 sample 路径供日志**，类型上刻意不做成
`Vec<PathBuf>`——免得下一个人看见一份「改动清单」就想拿它去决定同步什么。
任何「既然事件说改的是 a.txt，那就只同步 a.txt」的优化都会丢改动。

这与 M3a 对 `Transport::changes` 的处理是同一条纪律，理由也一样：
**判断一旦有第二个来源，两个来源就会分叉。**

## 另外三处取舍

- **只看 `Create`/`Modify`/`Remove`**。`Access`（含只读打开、mmap）会在备份/
  杀毒/全库索引扫描时暴涨，而它们一个字节都没改——把它们算作变更，等于让
  一次杀毒扫描触发一轮全库调和。这是 §4.8 hydration 风暴的近亲。
- **退避期间不接受 watcher 唤醒**。否则一个连不上的 hub，本地每存一次盘就
  重试一次，等于把退避架空（M3a 已对 longpoll 做过同样处置）。
- **心跳只写不读**。读取方在 `arca-cli`，按 FORMAT.md §9.7 自己解析，
  不共享类型——依赖方向是 agentd → cli，反过来会成环。第一版在 agentd 里
  也放了一个 `read`，那是个零生产调用者的 API（M2c 评审 I7 抓过同构的问题），
  而两份读法一旦并存就会分叉。

## 抓到一个教科书式的假绿

第一版 `is_internal` 写的是「路径关联不上数据集根就当作内部、不唤醒」，
看起来保守。但 **macOS 上 `/var` 是 `/private/var` 的符号链接**，FSEvents 报的
是规范化路径，于是**每一个事件的 `strip_prefix` 都失败**、全部被吞掉。

结果是：

- 「绝不自我唤醒」那条测试 —— **真空通过**
- 三条正例（受管文件改动产生唤醒、混合场景仍唤醒、连续写入合并）—— 同时失败

而「绝不自我唤醒」正是我在写测试时标注为**「本文件里最重要的一条」**的那个。
**如果当时只写了那条负例，这个 bug 会被当成「功能正常」交付。**

两处都改了：根同时保留原始与规范化两种形式；更要紧的是**把默认反过来**——
关联不上时**唤醒**而不是忽略。漏一次唤醒 = 一次静默丢失的改动（要等周期对账
才被发现）；多一次唤醒 = 一轮白跑的调和。两者代价差着数量级，而我第一版
选的是代价大的那边。

> 这是本项目第四次被同一类问题咬到（M0 逃生舱三次、M3a 反面夹具一次）。
> 共同形态是：**一个只验「不该发生的事没发生」的测试，在「什么都没发生」时
> 也会通过。** 负例必须配正例，否则它证明不了任何事。

## 真正缺的，按优先级

1. **每次唤醒仍做一次全量对账**（M3a 就列过）。现在唤醒变快了，这条的代价
   反而更显眼：大库上每次保存都触发一次全库扫描。真正的解法要 `arca-core`
   支持「只对这几条路径调和」——那是 core 的接口问题，不该由 agentd 私自解决
2. **溢出路径没有实机验证**。`Wake::Overflow` 的处置写好了、也有单元测试，
   但「真的把内核事件队列打爆」需要几十万个事件，没有在真机上跑过
3. **watcher 不认 `.gitignore`**。用户在受管目录里放一个 `node_modules/`
   会让每次 `npm install` 都触发唤醒。扫描侧已经按规则过滤，watcher 侧还没有
4. 退避**没有随机抖动**（M3a 列过，形态未变）
